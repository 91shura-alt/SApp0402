# SellerOps.App — инструкции для Codex

## Контекст проекта
Десктоп-приложение на **WPF (.NET)** для селлеров Wildberries.

Ключевые части:
- `Data/AppDbContext.cs` — EF Core + SQLite, путь к БД: `%LOCALAPPDATA%\\SellerOps\\sellerops.db`.
- `Data/AppDbContext.Upgrade.cs` — ручной апгрейд схемы SQLite (добавление таблиц/колонок).
- `Services/*` — интеграции с API WB, импорт, аналитика.
- `Views/*` — WPF-страницы (code-behind).

## Цели при доработках
1. **Минимальные правки** (small diffs), без переписывания архитектуры.
2. Сначала **фикс багов и стабильность** (чтобы не падало), потом фичи.
3. Любые изменения, влияющие на БД, должны быть совместимы с уже существующей БД пользователя.

## Как собирать/проверять
### Windows (рекомендуется)
- `dotnet restore`
- `dotnet build`

Если правки затрагивают БД/импорт:
- Запустить приложение, убедиться, что стартует без ошибок.
- Проверить действия:
  - `WB настройки` → сохранить токен
  - `WB товары` → синхронизация карточек
  - `Marketplace` → импорт заказов

### Важно
- Это WPF-проект (Windows-only). В Linux-среде сборка/запуск GUI может быть недоступен.

## Правила для правок по БД
- Не использовать миграции EF (пока). Схема обновляется через `EnsureUpgrade()`.
- Любое новое поле в Entity, которое сохраняется в SQLite, должно иметь:
  - `EnsureColumn(...)` в `AppDbContext.Upgrade.cs`
  - по необходимости `FixTextNullToEmpty(...)` для строк.

## Стиль кода
- C# 10/11, без усложнения.
- Новые методы — короткие, с понятными названиями.
- Ошибки пользователю: `MessageBox.Show(...)` с ясным текстом.

- "Добавь обработку rate-limit 429 и логирование ответов WB".
